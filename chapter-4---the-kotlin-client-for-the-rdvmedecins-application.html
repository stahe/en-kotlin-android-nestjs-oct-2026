    5. Chapter 4 - The Kotlin client for the RdvMedecins application

    5.1. Architecture Overview

    This client communicates with the course’s [rdvmedecins-nestjs-server] server—which remains completely unchanged—via the same routes: HTTP (POST [/login], GET [/getAllMedecins], GET [/getAllClients], GET [/getAgendaMedecinJour/:idMedecin/:jour], POST [/ajouterRv], POST [/supprimerRv]), with the same envelope JSON [{ status, data }] and the same token authentication [JWT] (header [Authorization: Bearer <jeton>]).

    // =========================================================================
// RdvMedecinsApplication.kt
// -------------------------------------------------------------------------
// First half of the Flutter version’s lib/main.dart: the build,
// UNE SEULE FOIS, the application’s services.
//
// Why an Application class? On Android, the screen (the Activity, see
// MainActivity) is DÉTRUIT and then RECRÉÉ every time the phone is rotated, with
// every time the system language changes, etc. Services created
// within the Activity would therefore be recreated with every rotation. The
// Application object, on the other hand, is created when the process starts and also lives
// as long as the process: this is the right place for objects that must
// last for the entire lifetime of the application. It is declared in
// AndroidManifest.xml (the android:name attribute of the <application> tag).
//
// The ORDRE of the builds matters, just as it does in the Flutter version:
// AuthService requires SettingsService (the server’s URL); the client
// The authenticated HTTP client requires AuthService (the token); RdvService requires
// requires the authenticated client HTTP and SettingsService.
// =========================================================================

package fr.rdvmedecins.client

import android.app.Application
import android.content.Context
import fr.rdvmedecins.client.core.http.AuthInterceptor
import fr.rdvmedecins.client.core.i18n.TranslationsService
import fr.rdvmedecins.client.core.services.AuthService
import fr.rdvmedecins.client.core.services.RdvService
import fr.rdvmedecins.client.core.services.SettingsService
import okhttp3.OkHttpClient
import java.util.concurrent.TimeUnit

class RdvMedecinsApplication : Application() {

     // lateinit: these non-null properties will be initialized in
     // onCreate(), not in the constructor (see the Kotlin tutorial)
    lateinit var settings: SettingsService
        private set
    lateinit var auth: AuthService
        private set
    lateinit var rdv: RdvService
        private set
    lateinit var translations: TranslationsService
        private set

     // called by Android when the app launches, before any screen is displayed
    override fun onCreate() {
        super.onCreate()

         // app preferences: a small key/value file
         // private, which survives after the app is stopped—the equivalent of
         // localStorage in a browser
        val prefs = getSharedPreferences("rdvmedecins", Context.MODE_PRIVATE)

         // 1. SettingsService first: the others depend on it
        settings = SettingsService(prefs)

         // 2. a “simple” client, HTTP OkHttp, used by AuthService for
             // POST /login. Short wait times: on mobile, a quick error message is better
             // a quick error message than an endless wait if the server is
             // unreachable (incorrect URL, Wi-Fi disconnected...).
        val httpSimple = OkHttpClient.Builder()
            .connectTimeout(10, TimeUnit.SECONDS)
            .readTimeout(15, TimeUnit.SECONDS)
            .build()
        auth = AuthService(settings, prefs, httpSimple)

         // 3. The authenticated client HTTP: a COPIE from the previous
             // (newBuilder() reuses its configuration and connections),
             // supplemented by the interceptor, which adds the token JWT
        val httpAuthentifie = httpSimple.newBuilder()
            .addInterceptor(AuthInterceptor(auth))
            .build()
        rdv = RdvService(httpAuthentifie, settings)

         // 4. Translations: no dependencies on other services
        translations = TranslationsService(assets, prefs)
    }
}

    Let’s comment on this code:

    • line 34: the class extends [android.app.Application]. Android creates a single instance of it when the app process starts—before any activity—and keeps it until the process ends;
    • lines 38–44: the four services, declared as [lateinit var ... private set]: non-null, initialized later (in [onCreate]), and modifiable only by this class;
    • line 54: [getSharedPreferences(...)]—the application’s preferences, a small private key/value file that survives application shutdown: the equivalent of a browser’s [localStorage] and Flutter’s [shared_preferences] package;
    • Lines 63–66: a “simple” [OkHttp] client, with short timeouts. A OkHttp client is designed to be PARTAGÉ: it manages its own pool of reusable connections;
    • line 67: [AuthService] receives the simple client: the [/login] route is the server’s only public route; it does not require a token;
    • lines 72–75: the authenticated client, [newBuilder()], creates a copy of it (which shares the connections of the first one) supplemented by the interceptor [AuthInterceptor], which adds the token JWT to each request (see [core/http]). [RdvService] receives it: none of its methods need to concern themselves with the token;
    • line 78: [assets]—access to the files in the application’s [assets/] folder, passed to [TranslationsService].

    A notable difference from the Flutter version: no asynchronous initialization is required before displaying the first screen. The [SharedPreferences] objects are read synchronously (they are loaded into memory upon first access): [AuthService] and [TranslationsService] read the stored session and language as soon as they are created, whereas [lib/main.dart] had to wait for [await auth.init()] and [await translations.init()].

// -------------------------------------------------------------------------
// All business responses from the server NestJS have the same format:
//
//      { "status": 0, "data": ... }
//
// where `status` is 0 if the operation is successful (see StatutReponse on the server side).
// The Flutter version decoded this envelope using a generic class
// Response<T>. Here, we proceed in DEUX real time, for a specific reason: in
// the event of an error, the server places a list of messages in "data"
// (List<String>), whereas in the event of success, we would expect, for example, a calendar.
// Decoding {status, data} directly into a Response<AgendaMedecinJour> would therefore fail
// resulting in an error response before even being able to read the status.
//    1. Read the envelope as a generic JSON tree (JsonObject);
//    2. Check the status; if it is 0 only, decode "data" in the
//       expected type.

package fr.rdvmedecins.client.core.models

import kotlinx.serialization.DeserializationStrategy
import kotlinx.serialization.json.Json
import kotlinx.serialization.json.JsonNull
import kotlinx.serialization.json.int
import kotlinx.serialization.json.jsonObject
import kotlinx.serialization.json.jsonPrimitive

// the JSON configuration shared by the entire client:
// - ignoreUnknownKeys: the server sends fields that this client
//    does not use (e.g., a doctor’s “version”)—these are ignored rather than
//    throwing an exception;
// - explicitNulls = false: during encoding, a null property is not
//    written (has no effect on this client’s classes, but more closely matches the
//    behavior of JSON.stringify on the JavaScript side).
val JsonRdv = Json {
    ignoreUnknownKeys = true
    explicitNulls = false
}

// exception thrown when the server responds with a business status other than
// from 0 (resource not found, invalid date, server error)
class ReponseException(val status: Int) :
    Exception("Le serveur a répondu avec le statut d'erreur $status")

// decodes the body of a response {status, data} and returns "data" in the
// T type described by [deserialiseur] (e.g., Medecin.serializer(), or
// ListSerializer(Medecin.serializer()) for a list of doctors)
fun <T> decoderReponse(corps: String, deserialiseur: DeserializationStrategy<T>): T {
     // 1. the envelope, in the form of a generic JSON tree
    val enveloppe = JsonRdv.parseToJsonElement(corps).jsonObject
     // 2. the business status
    val status = enveloppe.getValue("status").jsonPrimitive.int
    if (status != 0) {
        throw ReponseException(status)
    }
     // 3. “data,” decoded only now, in the expected type
    val data = enveloppe["data"] ?: JsonNull
    return JsonRdv.decodeFromJsonElement(deserialiseur, data)
}

     // while the server responds, SANS blocking the thread that calls it—
     // the equivalent of an async function returning a Future<LoginResultat>
     // on the Dart side. It throws an exception if the connection fails.
    // -----------------------------------------------------------------------

         // reserved for I/O. Android INTERDIT all network access
         // from the main thread (NetworkOnMainThreadException): this is
         // that draws the interface; it must never wait.

            val corps = JsonRdv.encodeToString(LoginDemande.serializer(), LoginDemande(login, password))
            val requete = Request.Builder()
                .url("${settings.apiBaseUrl}/login")
                .post(corps.toRequestBody(TYPE_JSON))
                .build()
             // execute(): call to BLOQUANT—safe here, since we’re on an
             // I/O thread. use { } closes the response at the end of the
             // block, no matter what happens (the equivalent of Java’s `try-with-resources`,
             // Java; see the Kotlin course).
            http.newCall(requete).execute().use { reponse ->
                 // Invalid credentials: the server returns a 401 Unauthorized response
                if (!reponse.isSuccessful) {
                    throw IOException("Échec de connexion (HTTP ${reponse.code})")
                }
                decoderReponse(reponse.body!!.string(), LoginResultat.serializer())
            }
        }
         // back on the caller's thread (the main thread):
         // it is here, and not on the I/O thread, that we modify
         // the state observed by the interface
        appliquerSession(resultat)
        prefs.edit { putString(CLE_SESSION, JsonRdv.encodeToString(LoginResultat.serializer(), resultat)) }
        return resultat
    }

    // -----------------------------------------------------------------------
     // Logout: the session is cleared from memory and from the preferences.
     // Must be called on the main thread (see AuthInterceptor).
    // -----------------------------------------------------------------------
    fun seDeconnecter() {
        accessToken = null
        login = null
        nom = null
        role = null
        estConnecte = false
        prefs.edit { remove(CLE_SESSION) }
    }

    private fun appliquerSession(session: LoginResultat) {
        accessToken = session.accessToken
        login = session.login
        nom = session.nom
        role = session.role
        estConnecte = true
    }

    companion object {
        private const val CLE_SESSION = "rdvmedecins.session"
        private val TYPE_JSON = "application/json; charset=utf-8".toMediaType()
    }

import android.os.Handler
import android.os.Looper
import fr.rdvmedecins.client.core.services.AuthService
import okhttp3.Interceptor
import okhttp3.Response

class AuthInterceptor(private val auth: AuthService) : Interceptor {

     // a Handler associated with the main thread: it allows work to be assigned to it
     // work from another thread (see intercept below)
    private val threadPrincipal = Handler(Looper.getMainLooper())

     // called by OkHttp for the CHAQUE request, on a network thread
    override fun intercept(chain: Interceptor.Chain): Response {
         // 1. The original request, supplemented with the token if one exists. A
             // The OkHttp request is immutable: newBuilder() creates a
             // editable copy.
        val jeton = auth.accessToken
        val requete = if (jeton == null) {
            chain.request()
        } else {
            chain.request().newBuilder()
                .header("Authorization", "Bearer $jeton")
                .build()
        }
         // 2. The request is allowed to continue on to the server
        val reponse = chain.proceed(requete)
         // 3. Token rejected: the user is logged out. This method
             // runs on a network thread; however, seDeconnecter() modifies
             // the state displayed by the interface: this call is therefore delegated to the
             // main thread (post), without waiting for it to execute—the
             // equivalent of unawaited(auth.seDeconnecter()) in the Flutter version.
        if (reponse.code == 401) {
            threadPrincipal.post { auth.seDeconnecter() }
        }
        return reponse
    }
}

class TranslationsService(
    private val assets: AssetManager,
    private val prefs: SharedPreferences,

     // the displayed language: a Compose state. As shown by t(...) below LIT
     // this property, any text displayed with t(...) is automatically
     // redisplayed when the language changes—no context.watch<...>() to
     // be written, unlike in the Flutter version.
    var langueCourante by mutableStateOf(prefs.getString(CLE_LANGUE, null) ?: LANGUE_PAR_DEFAUT)
        private set

     // the dictionaries already loaded, by language ("fr" -> {...})
    private val dictionnaires = mutableMapOf<String, JsonObject>()

    fun changerLangue(langue: String) {
        if (langue == langueCourante) {
            return
        }
        dictionnaire(langue) // loads the dictionary AVANT when switching languages
        langueCourante = langue
        prefs.edit { putString(CLE_LANGUE, langue) }
    }

    // -----------------------------------------------------------------------
     // t("LOGIN.TITLE"): iterates through the current language's dictionary
     // segment by segment ("LOGIN", then "TITLE"). If the key is
     // cannot be found, the key itself is returned: the missing text remains
     // thus visible on the screen, without causing the application to crash.
    // -----------------------------------------------------------------------
    fun t(cle: String): String {
        var valeurCourante: JsonElement = dictionnaire(langueCourante)
        for (segment in cle.split('.')) {
            valeurCourante = (valeurCourante as? JsonObject)?.get(segment) ?: return cle
        }
        val primitive = valeurCourante as? JsonPrimitive
        return if (primitive != null && primitive.isString) primitive.content else cle
    }

     // a language dictionary, loaded on first use and then kept in
     // memory. getOrPut: returns the value associated with the key, or executes
     // the block, stores its result, and returns it. Reading is
     // synchronous: both files contain only a few hundred
     // bytes in size, so they are read instantly.
    // -----------------------------------------------------------------------
    private fun dictionnaire(langue: String): JsonObject =
        dictionnaires.getOrPut(langue) {
            assets.open("i18n/$langue.json").bufferedReader().use { lecteur ->
                JsonRdv.parseToJsonElement(lecteur.readText()).jsonObject
            }
        }

    companion object {
        private const val CLE_LANGUE = "rdvmedecins.langue"
        private const val LANGUE_PAR_DEFAUT = "fr"
    }
}
